# Q&A — шпаргалка для защиты KnovaLand

> Держи под рукой. Отвечай коротко (20–40 сек), с опорой на «где это в коде».

## Общие

**1. Что это за проект, в двух словах?**
KnovaLand — платформа самообучения с геймификацией. Реализована на Django + DRF, покрывает полный путь: регистрация → запись на курс → постепенные уроки → проверка знаний → опыт и навыки.

**2. Какая главная фишка?**
Геймификация: опыт, уровни (общий и по каждому курсу), достижения, навыки в профиле, постепенное открытие уроков и RPG-тренажёр в конце каждого урока.

**3. Какие роли есть?**
Администратор (полный доступ), преподаватель (управляет только своими курсами/материалами/тестами), студент (просмотр материалов и прохождение тестов).

## Архитектура и стек

**4. Почему Django, а не FastAPI?**
ТЗ прямо требует Django + DRF. Плюс Django даёт готовую админку (требование «управление через admin»), ORM и встроенную авторизацию — меньше кода и выше надёжность.

**5. Почему PostgreSQL?**
Требование ТЗ. Это надёжная реляционная СУБД; я проверил работу проекта именно на PostgreSQL (миграции + тесты).

**6. Почему монолит, а не микросервисы?**
Для дипломного проекта микросервисы — избыточная сложность. Модульный монолит проще в разработке, тестировании и деплое. Разделение на приложения (users, courses, materials, testing, gamification, web) сохраняет границы ответственности.

**7. Из чего состоит проект?**
6 приложений: users (роли, JWT), courses (курс→раздел), materials (уроки), testing (тесты, проверка), gamification (опыт/уровни/навыки), web (геймифицированный UI).

**8. Что такое MTV в вашем проекте?**
Model-Template-View: модели — в `models.py`, шаблоны — в `templates/`, представления — во `views.py`. В API-части роль View играют DRF-сериализаторы и ViewSet'ы.

## Авторизация, JWT, безопасность

**9. Как работает JWT у вас?**
Через `djangorestframework-simplejwt`: `POST /api/auth/token/` выдаёт пару access/refresh, access живёт 60 минут, refresh — 7 дней. Все эндпоинты защищены классом `JWTAuthentication`.

**10. Как защищён API от неавторизованных?**
Глобально задано `DEFAULT_PERMISSION_CLASSES = IsAuthenticated`. Без токена запрос вернёт 401. Есть тест на это.

**11. Что за подтверждение email?**
При регистрации создаётся подписанный токен (TimestampSigner, срок 3 дня) и отправляется письмо со ссылкой. Переход по ссылке подтверждает email. Токен хранить в БД не нужно.

**12. Как настроен CORS?**
Через `django-cors-headers`. Разрешённые домены берутся из `.env` — только доверенные источники.

**13. Как хранятся пароли?**
Стандартный хеш Django (PBKDF2), плюс валидаторы пароля. Сырые пароли не хранятся.

**14. Правильные ответы можно получить через API?**
Нет. Для студента используется сериализатор без поля «правильно» — есть тест, который это проверяет.

## Права и роли

**15. Как реализованы права?**
Кастомные DRF-пермишены: `IsAdmin`, `IsOwnerOrAdmin`, `IsOwnerOrAdminOrReadOnly`, `IsStudent`. Для объектов с владельцем проверяется `obj.owner == request.user`.

**16. Как преподаватель ограничен своими курсами?**
В `get_queryset` и в пермишенах: изменение доступно только владельцу, чужой преподаватель получает 403. Покрыто тестами.

## Контент и CRUD

**17. CRUD есть и в admin, и в API — как избежали дублирования?**
Основное ядро — REST API на DRF (управление сущностями), а Django admin подключён к тем же моделям. Обе точки доступа работают с одними данными и правами.

**18. Что за ViewSet и Generic?**
Для полного CRUD использую `ModelViewSet` (базовый класс DRF), для отдельных действий — `ListAPIView`, `CreateAPIView`, `RetrieveAPIView`. Это и есть тэг Viewset/Generic.

## Тестирование знаний

**19. Как реализована проверка отдельным запросом?**
`POST /api/tests/{id}/submit/` принимает ответы, сервер считает баллы и возвращает результат. Логика вынесена в общий сервис, используют и API, и веб-тренажёр.

**20. Какие типы вопросов поддерживаются?**
Два: выбор ответа (чекбоксы) и ручной ввод (текст). Текстовый ответ нормализуется по регистру и пробелам, допускает несколько вариантов через `|`.

**21. Как считается результат?**
За каждый вопрос — верно/неверно. Процент = правильные / всего. Проходной балл задаётся у теста. Результат сохраняется как `TestSubmission`.

## Геймификация

**22. Как считаются уровни — общий и по курсу?**
Общий уровень профиля — по квадратичной шкале (уровень 2 — 100 XP, 3 — 300, 4 — 600). Уровень курса — свой, линейный: каждые 100 XP курса дают новый уровень. Они независимы.

**23. Как выдаются навыки?**
Уроки сгруппированы; за прохождение всей группы выдаётся навык (например, «Базовые знания Python»). Навыки видны в профиле в блоке «Мои скиллы» и в полном списке знаний.

**24. Как работает постепенное открытие?**
Урок открыт, если он первый или предыдущий уже пройден. Логика в сервисе `lesson_is_unlocked`.

**25. Где начисляется опыт?**
Через сигналы Django: за прохождение урока, за успешный тренажёр, за запись на курс. Так логика не дублируется.

## Качество и тестирование

**26. Сколько тестов и какое покрытие?**
95 тестов, покрытие 92% — выше требуемых 75%. Покрыты авторизация, права, CRUD, проверка тестов, геймификация и наполнение данными.

**27. Код соответствует PEP8?**
Да, `flake8` даёт ноль нарушений; настроены `black` и `isort`.

**28. Как проверяли?**
pytest + pytest-django. Есть сквозной сценарий: регистрация → курс → уроки → тренажёры → выдача навыков.

## Деплой и инфраструктура

**29. Как разворачивается проект?**
Docker + docker-compose: поднимаются веб-сервис (gunicorn) и PostgreSQL. Есть Dockerfile, requirements, пример `.env`.

**30. Почему Docker?**
Воспроизводимость окружения — «работает одинаково у всех». Закрывает тэги Docker и Docker-Compose.

## Бизнес

**31. В чём бизнес-ценность?**
Автоматизация проверки тестов экономит десятки часов преподавателей за поток (≈150 ч), геймификация повышает удержание студентов, а open-source стек снижает стоимость владения. Подробно — в бизнес-блоке.

## Сложности и развитие

**32. Что было самым сложным?**
Геймификация: связать опыт, уровни, навыки и постепенное открытие так, чтобы переходы срабатывали автоматически на события (сигналы). Нашёл и исправил баг, когда опыт за тренажёр не начислялся, потому что результат сохранялся не при создании записи.

**33. Что бы улучшили дальше?**
Аналитика для преподавателя, экспорт отчётов в CSV, интеграция с внешними API, мобильное приложение, асинхронная обработка тяжёлых задач.

**34. Есть ли тэги, которых у проекта нет?** (если спросят про легенду тэгов)
Да, часть тэгов из библиотеки — про другие стеки (MongoDB, FastAPI, Tortoise) или про необязательные функции (CSV, nginx, Telegram); их можно добавить как развитие. У проекта закрыты тэги Django, DRF, PostgreSQL, ORM, JWT, CORS, Permissions, Serializers, Viewset/Generic, Tests, README, PEP8, Git, OpenAPI Docs, а также Templates, Forms, Auth, CBV/FBV, MVT/MTV, Filter, Docker, Docker-Compose, JSON, Regex.
